# supplier-search: חיפוש מאוחד אצל כל הספקים

מערכת שמחפשת מוצר בבת אחת בכל אתרי המפיצים (טכנו-רצף, ויזואל, אמטל, מור לוי, סי-דאטה,
CMS, גראנד אדוונס), מאחדת את התוצאות לרשימה אחת, ומאפשרת סינון מלא ומיון לפי מחיר.

רצה על מחשב במשרד: כתובת IP ישראלית ודפדפן Chrome אמיתי. כך עוברים את Cloudflare,
ונשמרות ההתחברויות כמשווק.

## מה יש בממשק

- **חיפוש אחד בכל הספקים במקביל.** אתר איטי או תקול לא מעכב את האחרים, והשגיאה שלו
  מוצגת ליד שמו.
- **סינונים:** ספק, יצרן, מעבד, זיכרון, נפח אחסון, גודל מסך, כרטיס מסך, מערכת הפעלה,
  מלאי, טווח מחירים, "חייב להכיל" ו"לא להכיל", ורק תוצאות שמכילות את כל מילות החיפוש.
  ליד כל ערך מוצג כמה תוצאות יש לו. המפרט מזוהה משם המוצר, כולל הקיצורים של המפיצים
  (`U7-355` הוא Core Ultra 7, `R5 5625U` הוא Ryzen 5, `W11P`, `512NVME`, `S27-4e` הוא מסך 27").
- **מיון לפי מפרט:** מעבד (מהחזק לחלש או הפוך), גודל מסך, זיכרון RAM, נפח אחסון וכרטיס
  מסך. המעבדים מדורגים לפי רמה, ו-Intel, AMD ו-Apple באותה רמה מוצגים יחד
  (למשל Core i5 ליד Ryzen 5). בתוך כל רמה המוצר הזול מופיע ראשון, ומוצרים שבשמם לא מופיע
  המפרט מוצגים בסוף. גם רשימות הסינון של מעבד, מסך וכו' ממוינות כך.
- **חיפוש מעמיק (לא חובה):** כשבשם המוצר חסר מפרט, למשל אצל ויזואל שבשם יש רק קוד דגם,
  מסמנים "חיפוש מעמיק". המערכת פותחת את דף המוצר וקוראת ממנו מעבד, זיכרון, אחסון, מסך
  ומערכת הפעלה, וכך גם המוצרים האלה נכנסים לסינון ולמיון. זה איטי יותר: נפתחים עד 20 דפים
  לכל ספק, ורק של מחשבים ומסכים שחסר להם מפרט. מפרט שנקרא נשמר ליום, כך שבפעם הבאה זה
  מהיר. מוצר שהמפרט שלו נקרא מדף המוצר מסומן "מפרט מדף המוצר". מגדירים את זה לכל אתר
  ב-`detail` ב-`sites.yaml`.
- **אינדקס מקומי, תשובה מיידית:** המערכת שומרת אצלה את המוצרים של כל הספקים (SQLite עם
  חיפוש טקסט מלא), כך שחיפוש עונה תוך אלפיות שנייה במקום לחכות לאתרים:
  - **מה נכנס:** כל חיפוש חי מתווסף לאינדקס. בנוסף, עדכון ברקע (כל 12 שעות, מוגדר ב-`index:`
    ב-`sites.yaml`) מריץ אצל כל ספק רשימת חיפושים רחבה של מותגים וקטגוריות, כדי לכסות את הקטלוג.
  - **מה מוצג:** אם במה שחיפשת אין שום דבר באינדקס, החיפוש עובר לאתרים לבד. מוצר שלא נראה 3
    ימים לא מוצג מהאינדקס. ליד כל ספק מוצג מתי המוצרים שלו נאספו.
  - **לחיפוש באתרים עכשיו:** בוחרים "מקור: חי מהאתרים" או מסמנים "רענון מלא".
  - **ניהול:** בעמוד הניהול רואים כמה מוצרים יש לכל ספק, ויש כפתור "עדכון האינדקס עכשיו".
  - **שמירת סיסמה לספק:** כששומרים סיסמה לספק, המוצרים שלו נמחקים מהאינדקס ונאספים מחדש
    עם המחירים.
  - **ב-Fly:** כשהמכונה מושהית אין עדכון ברקע. העדכון ירוץ כשהיא תתעורר ויתברר שהגיע הזמן.
- **מחיר כולל מע"מ או לפני מע"מ.** הנתונים מנורמלים לשקלים: כל אתר מוגדר אם המחיר שלו
  כולל מע"מ. מחיר בדולרים מומר לפי השער היציג של בנק ישראל.
- **תצוגת השוואה.** אותו מוצר אצל כמה ספקים (לפי מק"ט יצרן) מוצג בכרטיס אחד, ממוין מהזול
  ליקר.
- **זיכרון זמני.** תוצאות נשמרות 10 דקות, כך ששינוי סינון לא מושך שוב מהאתרים. "רענון
  מלא" מושך מחדש.

## התקנה (Windows)

1. מתקינים Python 3.11 ומעלה מ-python.org, ומסמנים "Add python.exe to PATH". מומלץ
   שיהיה מותקן גם Google Chrome.
2. מורידים את הפרויקט ולוחצים פעמיים על `install.bat`.
3. לוחצים פעמיים על `run.bat`. הדפדפן ייפתח בכתובת `http://localhost:8765`.

## חיפוש AI

עמוד **חיפוש AI** (קישור בראש המסך) מקבל תיאור חופשי או קוד מוצר, למשל
"מחשב נייד 14 אינץ' עם i5 ו-16GB, עד 3,000 ש"ח" או `21X8002RIV`, ומוצא את המוצר עצמו,
או את הקרובים אליו ביותר שיש לספקים במלאי.

**איך זה עובד:** Claude (מודל `claude-opus-5-5` של Anthropic) מריץ בעצמו כמה חיפושים אצל כל
הספקים, דרך אותו מנוע חיפוש של המערכת. כשחסר לו מפתח בשם המוצר, הוא פותח את דף המוצר. בסוף
הוא מחזיר רשימה מדורגת: **זהה**, **קרוב** או **חלופה**, עם הסבר בעברית למה כל מוצר מתאים
ובמה הוא שונה. מוצרים עם אותו מק"ט יצרן אצל כמה ספקים מוצגים כולם, להשוואת מחירים.

**הגדרה:** מנהל שומר בעמוד **ניהול → חיפוש AI** מפתח API של Anthropic. יוצרים מפתח ב-
https://console.anthropic.com/settings/keys. המפתח נשמר מוצפן, משמש את כל המשתמשים, ואי אפשר
לצפות בו אחרי השמירה. כפתור "בדיקת מפתח" מוודא שהמפתח תקין, בלי עלות.

**עלות:** כל חיפוש AI עולה בדרך כלל כמה סנטים. העלות המשוערת מוצגת בסוף כל חיפוש, והחיוב
עצמו מופיע בחשבון ה-Anthropic שלך. לכל שאלה יש לכל היותר 6 סבבי חיפוש.

## משתמשים והרשאות

לכל מי שמשתמש במערכת יש שם משתמש וסיסמה משלו. יש שני תפקידים:

- **מנהל:** מוסיף ומוחק משתמשים, מאפס סיסמאות, ושומר את הסיסמאות לאתרי הספקים.
- **משתמש:** מחפש בלבד.

מנהלים את זה בעמוד **ניהול** (קישור בראש המסך, למנהלים בלבד). כל משתמש יכול להחליף לעצמו
את הסיסמה דרך "שינוי סיסמה".

**המנהל הראשון:**
- **ב-Fly:** נוצר אוטומטית בהפעלה הראשונה. שם המשתמש הוא `admin` והסיסמה היא ה-secret
  `APP_PASSWORD`. אחרי הכניסה הראשונה כדאי להוסיף משתמשים, ואפשר גם להחליף את הסיסמה.
- **במחשב המשרד:** כל עוד אין משתמשים המערכת פתוחה. נכנסים לעמוד הניהול ויוצרים משתמש,
  והראשון שנוצר הוא תמיד מנהל. מאותו רגע הכניסה היא עם שם משתמש וסיסמה.

אחרי 5 ניסיונות כניסה שגויים, שם המשתמש ננעל לרבע שעה. התחברות נשמרת 30 יום.

## סיסמאות לאתרי הספקים (משותפות)

המנהל שומר בעמוד **ניהול → סיסמאות לאתרי הספקים** שם משתמש וסיסמה לכל ספק. הסיסמאות
משותפות לכל המשתמשים: כל חיפוש של כל משתמש מתחבר לספקים עם הפרטים האלה ומקבל מחירי משווק.

- **הסיסמאות נשמרות מוצפנות**, ואף אחד לא יכול לצפות בהן מהממשק, גם לא מנהל. השרת משתמש בהן
  רק כדי להתחבר לספקים. כדי להחליף סיסמה מזינים חדשה. כדי לשנות רק את שם המשתמש, משאירים את
  שדה הסיסמה ריק.
- **"בדיקת התחברות"** מתחברת לאתר עם הפרטים השמורים ומדווחת אם ההתחברות הצליחה. כך יודעים
  מיד אם הסיסמה נכונה, ואם האתר מוגדר נכון.
- **מפתח ההצפנה:** ב-Fly הוא נוצר אוטומטית בפרסום הראשון ונשמר כ-secret בשם `SECRET_KEY`.
  אין לשנות או למחוק אותו, אחרת יהיה צריך להזין מחדש את כל סיסמאות הספקים. במחשב המשרד
  המפתח נשמר בקובץ `data/secret.key`.

## התחברות כמשווק

רוב הספקים מציגים מחירים ומלאי רק למשווק מחובר. בלי התחברות רואים את המוצרים, המק"טים
והמלאי (חלקית), בלי מחיר, ולצד שם האתר מופיעה אזהרה "לא מחובר".

אפשר להתחבר בשתי דרכים:

- **מהממשק (מומלץ):** בעמוד הניהול, כמו שמתואר למעלה.
- **מקובץ:** מעתיקים את `config/credentials.example.yaml` ל-`config/credentials.yaml`
  (ההתקנה עושה זאת לבד) וממלאים שם משתמש וסיסמה לכל אתר. הקובץ לא נשמר ב-git.
  ```yaml
  techno:
    username: "mail@example.com"
    password: "..."
  ```
- **ידנית:** לוחצים "התחברות" ליד שם האתר. במחשב השרת ייפתח חלון Chrome. מתחברים בו
  (גם עם קוד SMS או captcha) וסוגרים את החלון. ההתחברות נשמרת בפרופיל של האתר תחת
  `data/profiles/` וממשיכה לעבוד בחיפושים הבאים.

## הוספת אתר חדש או תיקון אתר

כל אתר מוגדר ב-`config/sites.yaml`: כתובת החיפוש, וסלקטורים של CSS לכל שדה (שם, מחיר,
מלאי, מק"ט). התחביר מתועד בראש `supsearch/parse.py`. אין צורך לשנות קוד Python.

**אתר שעוד לא הוגדר** (CMS וגראנד אדוונס חסומים מבחוץ ולכן עוד לא הוגדרו):

1. לוחצים "פתח והקלט" ליד שם האתר.
2. בחלון שנפתח מתחברים, מחפשים מוצר אחד (למשל `ssd`) ופותחים עמוד שני של תוצאות.
3. סוגרים את החלון.
4. כל עמוד שנפתח נשמר ב-`data/captures/<id>/`. שולחים את התיקייה, ולפיה כותבים את
   ההגדרה.

אותה דרך עובדת לאימות אתר שכבר מוגדר אחרי התחברות. למשל, הסלקטור של המחיר בטכנו-רצף
נכתב בלי חשבון משווק.

## גישה ממחשבים אחרים ברשת

ברירת המחדל היא האזנה רק ל-`localhost`. כדי לגשת מעמדות אחרות, מוסיפים ל-`run.bat` לפני
הפעלת השרת:

```bat
set HOST=0.0.0.0
```

כל משתמש נכנס עם שם המשתמש והסיסמה שלו. כל עוד אין משתמשים, המערכת נפתחת רק מהדפדפן של
המחשב עצמו, ולא מעמדות אחרות. לכן קודם יוצרים מנהל במחשב השרת.

## העלאה ל-Fly.io

כל `push` לענף `main` מריץ את הבדיקות ב-GitHub Actions, ואם הן עוברות מפרסם ל-Fly
(`.github/workflows/deploy.yml`). בפרסום הראשון האפליקציה ונפח האחסון נוצרים אוטומטית.

**הגדרה חד-פעמית:** ב-GitHub, בהגדרות הריפו, תחת Settings → Secrets and variables →
Actions → New repository secret, מוסיפים:

| Secret | מה לשים |
|--------|---------|
| `FLY_API_TOKEN` | טוקן מ-Fly: בלוח הבקרה תחת Tokens, או בפקודה `fly tokens create org` |
| `APP_PASSWORD` | הסיסמה של המנהל הראשון (שם משתמש `admin`). **חובה**: בלעדיה השרת נעול |

אחרי שמוסיפים את ה-secrets מריצים את ה-workflow מחדש: בלשונית Actions בוחרים
"test and deploy" ולוחצים "Run workflow". אם חשבון ה-Fly שייך לארגון שאינו `personal`,
מגדירים גם משתנה (Variable) בשם `FLY_ORG`.

הכתובת: `https://bsd-supplier-search.fly.dev`. נכנסים עם שם המשתמש `admin` והסיסמה
מ-`APP_PASSWORD`, ומשם מוסיפים משתמשים ושומרים את סיסמאות הספקים בעמוד הניהול.

**ההבדלים מהרצה במשרד:**
- **אין חלון התחברות** (לשרת אין מסך). ההתחברות לספקים נעשית רק עם הסיסמאות השמורות
  בעמוד הניהול. אתר שדורש קוד SMS או captcha בהתחברות יעבוד רק כאורח.
- **כתובת IP של ענן (פרנקפורט).** CMS, גראנד אדוונס וסי-דאטה חוסמים כתובות כאלה.
  הפתרון: יציאה דרך המשרד עם Tailscale (בסעיף הבא).
- **עלות:** אחרי כמה דקות בלי שימוש, Fly משהה את המכונה (`suspend`) ומפסיק לחייב על מעבד וזיכרון.
  נשאר רק תשלום קטן על האחסון. הכניסה הבאה מעירה אותה תוך שניות, והיא ממשיכה מאותו מקום.
  את זמן ההמתנה המדויק קובע Fly, ואי אפשר לשנות אותו.

## יציאה דרך ה-IP של המשרד (Tailscale)

השרת ב-Fly מצטרף לרשת ה-Tailscale שלך, וכל הגלישה שלו לאתרי הספקים יוצאת דרך מחשב
במשרד שמוגדר כ-**exit node**. הספקים רואים את ה-IP הישראלי של המשרד, כאילו החיפוש נעשה
משם. על מחשב המשרד צריך רק את Tailscale, בלי Python ובלי התקנה של המערכת.

**במחשב המשרד** (Windows, צריך להישאר דלוק):
1. מתקינים את Tailscale מ-https://tailscale.com/download ומתחברים.
2. לוחצים לחיצה ימנית על האייקון של Tailscale ליד השעון, ובוחרים Exit node → Run exit node.
3. בלוח הניהול https://login.tailscale.com/admin/machines, ליד המחשב, לוחצים ⋯:
   - **Edit route settings**: מסמנים Use as exit node.
   - **Disable key expiry**: כדי שהחיבור לא יפוג אחרי כמה חודשים.
4. בהגדרות החשמל של Windows מבטלים שינה.

**מפתח לשרת:** בלוח הניהול, תחת Settings → Keys → Generate auth key, יוצרים מפתח ומסמנים
Reusable.

**ב-GitHub secrets** (באותו מקום כמו `FLY_API_TOKEN`):

| Secret | מה לשים |
|--------|---------|
| `TS_AUTHKEY` | המפתח שנוצר (`tskey-auth-...`) |
| `TS_EXIT_NODE` | שם מחשב המשרד כפי שמופיע ב-Tailscale, או כתובת ה-`100.x.x.x` שלו |

מריצים שוב את ה-workflow. בראש הממשק יופיע "יוצא דרך המשרד" בירוק. אם מחשב המשרד
כבוי, ליד כל ספק תופיע ההודעה "אין יציאה דרך מחשב המשרד". אם ההגדרה עצמה נכשלה, יופיע
"Tailscale לא מחובר - יוצא ישירות" באדום.

אתר שעובד טוב גם מהענן אפשר להוציא ישירות, בלי לעבור דרך המשרד: מוסיפים לו `direct: true`
ב-`sites.yaml`.

## מבנה

| קובץ | תפקיד |
|------|-------|
| `config/sites.yaml` | הגדרת כל אתר: כתובת חיפוש, שיטת הורדה, סלקטורים |
| `supsearch/fetch.py` | הורדת דפים: HTTP רגיל, או Chrome עם פרופיל קבוע לכל אתר |
| `supsearch/parse.py` | חילוץ מוצרים מהדף לפי ההגדרה |
| `supsearch/normalize.py` | מחיר, מע"מ, מלאי, מק"ט, וזיהוי מפרט מהשם |
| `supsearch/filters.py` | סינון, ספירות ליד כל ערך סינון, מיון, וקיבוץ לפי מק"ט יצרן |
| `supsearch/aggregator.py` | חיפוש מקבילי, זיכרון זמני, שער דולר |
| `supsearch/index.py` | האינדקס המקומי, החיפוש שמתחיל ממנו, והעדכון ברקע |
| `supsearch/detail.py` | חיפוש מעמיק: קריאת מפרט מדף המוצר |
| `supsearch/ai.py` | חיפוש AI: השיחה עם Claude והכלים שלו |
